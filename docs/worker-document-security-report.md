# Worker Document Security & Protection Report

This document details the security safeguards implemented in the Hyperlocal Marketplace to protect sensitive worker KYC documents (Aadhaar, PAN, etc.) from unauthorized access, uploads, and data leakage.

## 1. Upload Sanitization and Validation
All document uploads pass through a robust validation pipeline (`backend/src/utils/fileValidator.js`) before being processed by the storage engine:

* **File Type (MIME) Restricting**: Only secure, static image formats (`image/jpeg`, `image/png`) and document formats (`application/pdf`) are allowed. Executables, scripts, and other active file types are strictly blocked.
* **Size Enforcement**: File uploads are capped at 5 MB per file. Any upload exceeding this limit is rejected with a `400 Bad Request` before disk write occurs.
* **Double Extension Filtering**: File names are checked for double extension bypass patterns (e.g., `malware.png.exe`). The upload is immediately blocked if detected.
* **Null Byte Detection**: Checked for null bytes (`%00`, `\0`) in the multipart filename or headers. These are caught during parse time and return `400 Bad Request`.
* **Path Traversal Shielding**: Filenames are URL-decoded and checked for directory traversal patterns (`../`, `..\`, `/`, `\`). This ensures Multer uploads remain confined strictly to the designated target directory and cannot write to system paths.

## 2. Encryption of Sensitive Identifiers
To prevent unauthorized database leakage of personal identifiers (e.g., full Aadhaar card numbers, PAN numbers):
* **AES-256-GCM Encryption**: Full document numbers are encrypted using AES-256-GCM before database write. The initialization vector (IV) and authentication tag are stored alongside the encrypted payload.
* **Last 4 Digits Disclosure**: Only the last 4 digits of the card (e.g., `•••• •••• 1234`) are stored as plaintext to allow user dashboard verification.
* **Deterministic Hashing**: A SHA-256 hash of the normalized document number is stored as a deterministic lookup index (`documentNumberHash`). This enables duplicate checking (e.g., ensuring a single Aadhaar number cannot register on multiple accounts) without storing the document number in plaintext.

## 3. Strict Document Access Control
* **Owner-Only & Admin-Only Enforcement**: A middleware validates that document access is authorized. Only the owner worker who uploaded the document, or a verified admin user, can access the document download/view API.
* **Temporary Signed URLs**: Documents are stored in a private directory. The server generates secure, short-lived, signed URLs for document retrieval. These URLs expire automatically after 10 minutes.
* **No Cache Directives**: Headers (`Cache-Control: private, no-store`) are set for all document view responses to prevent intermediate proxy servers or shared local machines from caching sensitive identity cards.

## 4. Sensitive Data Masking & Redaction
* **DTO Exclusion**: Public worker search results, profile view responses, and API DTOs strictly exclude document IDs, document status fields, and encrypted document numbers.
* **Log Redaction**: Standard structured logs generated by `pino` redact `documentNumber`, `vpa`, `accountNumber`, and verification signatures in metadata payloads before writing to log streams.
* **Audit Trails Masking**: Audit logs track that an admin viewed a document, but strictly exclude the temporary signed URL token, signature, or original document number from the metadata record.
